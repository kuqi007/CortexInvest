## 四大风险（Agent 共识）

### 🔴 风险 1：WAL 文件未复制（高风险）

**问题**：
```bash
# 当前 Cron 命令
*/2 * * * * cp .../sim_trading.db ~/.ai-investor-data-local/sim_trading.db
```

SQLite WAL 模式产生 3 个文件：
- `sim_trading.db` - 主数据库
- `sim_trading.db-wal` - 预写日志（最新数据）
- `sim_trading.db-shm` - 共享内存索引

**后果**：只复制 `.db` 文件，可能丢失**最近几秒到几分钟**的未 checkpoint 数据。

**修复**（已实施）：
```bash
# 使用 SQLite 在线备份 API
sqlite3 "/path/to/source.db" ".backup to '/path/to/dest.db'"
```

---

### 🟡 风险 2：竞态条件（中风险）

**场景**：
```
T0: 生产机开始事务写入
T1: OneDrive 开始同步（文件处于中间状态）
T2: Cron 执行复制 → 复制到不完整文件
T3: Web 读取 → 可能读到损坏/不完整数据
```

**缓解措施**（已实施）：
- 使用 `flock` 防止并发执行
- 原子替换（先复制到 .tmp，再 mv）

---

### 🟡 风险 3：数据延迟（业务风险）

**延迟构成**：
- Cron 间隔：2分钟
- OneDrive 同步：1-3分钟
- **实际延迟：3-5分钟**

**业务影响**：

| 功能 | 容忍度 | 影响 |
|------|--------|------|
| Alerts | ⚠️ **边际** | 可能错过最佳决策时机 |
| 价格快照 | ✅ 可接受 | 监控用，非交易依据 |
| 持仓盈亏 | ✅ 可接受 | 参考值 |

**建议**：缩短 Cron 间隔至 30 秒，或添加数据新鲜度指示器。

---

### 🔴 风险 4：静默故障（高风险）

**问题**：
- Cron 失败无告警
- OneDrive 同步卡住无感知
- 用户可能基于**几小时前的数据**做决策

**缓解措施**（已实施）：
```bash
# 数据新鲜度检查（每5分钟）
*/5 * * * * [ $(find ~/.ai-investor-data-local/sim_trading.db -mmin +5 | wc -l) -eq 0 ] || echo "ALERT: DB stale at $(date)"
```

## 已实施的改进

### 1. SQLite 在线备份（替代 cp）
```bash
sqlite3 ".../sim_trading.db" ".backup to '/local/sim_trading.db.tmp'" \
  && mv "/local/sim_trading.db.tmp" "/local/sim_trading.db"
```

### 2. 文件锁防止并发
```bash
flock -n /tmp/sim_trading_sync.lock -c '...'
```

### 3. 数据新鲜度监控
```bash
*/5 * * * * [ $(find ~/.ai-investor-data-local/sim_trading.db -mmin +5 | wc -l) -eq 0 ] || echo "ALERT: ..."
```

### 4. 同步日志
```bash
>> ~/.ai-investor-sync.log 2>&1
```
