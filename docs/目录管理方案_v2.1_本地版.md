## 二、三个核心文件

### 数据流向（单一 truth source）

```
valuation_result.json  ──→  metadata.json（给 catalog 索引用）
                   └──→  report.md（给人阅读）
```

**valuation_result.json 是唯一数据源**，metadata 和 report 都是它的投影，不存在双写不一致。

## 三、命名规范

| 项目 | 规则 | 示例 |
|------|------|------|
| 股票目录 | `{中文名}_{市场前缀}{代码}` | `腾讯控股_HK00700` |
| 版本目录 | `v{N}_{YYYY-MM-DD}` | `v1_2026-04-18` |
| 分析报告 | `{股票名}_{代码}_v{N}_{日期}.md` | `腾讯控股_HK00700_v1_2026-04-18.md` |
| 原始数据 | 保持原始文件名 | `mx_data_查询腾讯控股最新股价_raw.json` |

**市场前缀**：港股=`HK`，沪市=`SH`，深市=`SZ`

## 四、复盘机制

### 触发条件

| 触发方式 | 条件 |
|----------|------|
| 手动 | 用户说「复盘腾讯」 |
| 价格偏离 | 股价偏离中性估值 ±15% |
| 财报季 | 年报(4月)/中报(8月)/季报(10月) 发布后 |
| 定期 | 超过 review_interval_days（默认90天） |

### 对比输出

复盘时 Hermes 自动：
1. 读取上一版 valuation_result.json
2. 与新版逐字段对比（营收增速、毛利率、估值水位）
3. 生成 `changes_from_previous` 写入新 metadata.json
4. 飞书通知用户关键变化

---

## 五、Hermes Agent 工作流

```
用户：「分析腾讯控股」
  │
  ① 查 catalog.json → 命中 HK00700
  │    ├── 不存在 → 新建目录
  │    └── 存在 → 读最新 metadata，判断是否需要复盘
  │
  ② 创建 v{N}_{日期}/ 目录
  │
  ③ 数据采集 → data/（mx_data + mx_search）
  │
  ④ Skill 分析 → 生成 valuation_result.json（结构化）
  │
  ⑤ 渲染两份产物：
  │    ├── report.md（人读）
  │    └── metadata.json（自动从 valuation_result 提取）
  │
  ⑥ 如有旧版本 → 自动对比，填入 changes_from_previous
  │
  ⑦ 更新 catalog.json（latest_version++）
  │
  ⑧ 飞书通知：估值、vs上版变化
```
