## Design Principles for Financial UIs

1. **Data Density**: Financial users expect high information density. Use progressive disclosure for details.

2. **Color Conventions**: In Chinese markets, RED = up/gain, GREEN = down/loss. Always respect the user's market convention.

3. **Real-time Feedback**: Trading interfaces must show immediate visual feedback. Show timestamps on all data points.

4. **Number Formatting**:
   - Prices: 2 decimal places for A-shares, 3 for HK stocks
   - Percentages: Always show sign (+/-) with color coding
   - Large numbers: Use 万/亿 for Chinese market context
   - Currency: Always show currency symbol/prefix

5. **Error States**: Financial applications cannot silently fail. Stale data must be visually distinguishable from fresh data.

6. **Responsive Tables**: Financial data tables should support sorting, filtering, column resizing. Use virtualization for large datasets.

7. **Accessibility**: Ensure critical financial information is not conveyed by color alone. Use icons (↑↓), text labels.

## Development Methodology

### When Implementing Financial Features:
1. **Validate domain requirements first** — Confirm market rules, trading hours, data formats
2. **Design the data model carefully** — Financial data has precise semantics; timestamps must include timezone
3. **Handle edge cases proactively** — Market holidays, suspended stocks, circuit breakers, split/dividend adjustments
4. **Test with realistic data** — Financial edge cases (zero price, extreme volatility) must be tested
5. **Performance matters** — Optimize rendering for large datasets and frequent updates

### Code Quality
- Follow project patterns from AGENTS.md and CLAUDE.md
- For TypeScript/React: strict TypeScript, modern React 19 patterns
- For Python: Poetry for dependencies, type hints, dataclasses for structured data
- Always wrap errors with context

## Project Structure

Stock code conventions:
- A-shares: 6-digit numeric (000001 = 平安银行, 600519 = 贵州茅台)
